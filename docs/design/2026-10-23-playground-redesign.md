# 设计稿：Playground 界面重构

> 按项目约定：**先出设计，再写实现。**

## 一、问题诊断

### 1.1 现状

顶部一条 49px 的通栏 header，挤了 4 个控件：

```
FBK Playground   [Adapter▾] [Theme▾] [Demo▾ 很宽] [查看源码]
```

内容区是一张孤零零的表格，**没有任何标题、说明或上下文**。

### 1.2 具体问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | Demo 下拉框里是 14 个扁平选项，无分组 | 找不到东西，只能逐个翻 |
| 2 | 内容区没有 demo 标题与说明 | 不知道在看什么、该看哪里 |
| 3 | 源码面板是 `<pre>` 直接铺在 demo 下面 | 挤占内容区，长源码要滚很久 |
| 4 | 顶部控件是手写原生 `<select>` + 手写 CSS | **本末倒置**：playground 是消费方应用，不受零依赖约束，却手搓了 200 行 CSS 去模仿 UI 库 |
| 5 | 没有「当前 demo 属于哪一类」的信息 | 14 个 demo 混在一起，缺少导航心智 |
| 6 | 无法直接链接到某个 demo | 分享/回归测试只能靠手点 |

### 1.3 根本认知修正

**Playground 是「外部消费方」，不是库的一部分。**

它模拟的是真实业务项目接入组件库的场景。真实项目里：

- 用 element-plus 的 `el-select`，不会手写 `<select>` + `appearance: none`
- 用 `el-switch` 做开关，不会手搓 checkbox
- 用现成的布局容器

因此 `apps/playground` 可以（也应该）直接依赖 UI 库。
之前为了「统一到设计系统」而手写原生控件，方向就错了 ——
那 200 行 CSS 本质上是在重新实现 UI 库已经提供的东西。

---

## 二、设计目标

1. **可发现**：14 个 demo 分组、可搜索、URL 可直达
2. **可理解**：每个 demo 有标题、说明、所属分类
3. **不干扰**：源码面板按需展开，不挤占 demo 区域
4. **用对工具**：顶部控件直接用 element-plus，不再手写

---

## 三、布局方案

### 3.1 整体：左侧栏 + 右侧内容

```
┌────────────┬──────────────────────────────────────────────┐
│            │  ┌─ 顶栏 ─────────────────────────────────┐  │
│  FBK       │  │ 基础表格            [源码] [适配器▾][主题▾] │  │
│ Playground │  └────────────────────────────────────────┘  │
│            │                                              │
│ ┌ 搜索 ─┐  │  ┌─ Demo 说明条 ──────────────────────────┐  │
│ │🔍      │  │  │ 分页 + 排序 + 服务端请求的典型列表      │  │
│ └────────┘  │  └────────────────────────────────────────┘  │
│            │                                              │
│ 表格 5      │  ┌────────────────────────────────────────┐  │
│  基础表格 ● │  │                                        │  │
│  查询联动   │  │            Demo 内容区                  │  │
│  多选       │  │                                        │  │
│  行内编辑   │  │                                        │  │
│  空态       │  │                                        │  │
│            │  └────────────────────────────────────────┘  │
│ 表单 4      │                                              │
│  查询表单   │                                              │
│  表单生成   │                                              │
│  ...       │                                              │
│            │                                              │
│ 数据展示 3  │                                              │
│  ...       │                                              │
└────────────┴──────────────────────────────────────────────┘
```

**为什么改成侧边栏**：
- 14 个 demo 用下拉框是「隐式列表」，用侧边栏是「显式列表」——一眼看到全部
- 分组后能建立心智模型（表格/表单/数据展示/反馈/看板/大屏）
- 顶部栏只留「当前在哪」和「全局开关」，职责单一

### 3.2 侧边栏规格

| 项 | 值 |
|---|---|
| 宽度 | 240px |
| 背景 | `--fbk-color-bg-container` |
| 右侧分隔线 | `1px solid var(--fbk-color-border-light)` |
| 分组标题 | 12px，`--fbk-color-text-tertiary`，大写间距 |
| 菜单项 | 14px，高 34px，`--fbk-radius-md` 圆角 |
| 激活项 | `--fbk-color-primary-bg` 底 + `--fbk-color-primary-text` 字 + 左侧 2px 竖条 |
| 搜索框 | 顶部固定，`--fbk-spacing-sm` 内边距 |

### 3.3 顶栏规格

| 项 | 值 |
|---|---|
| 高度 | 56px |
| 左侧 | 当前 demo 标题（16px semibold）+ 分类标签 |
| 右侧 | 源码开关（`el-switch`）、适配器（`el-select`）、主题（`el-select`） |
| 底部 | `1px solid var(--fbk-color-border-light)` |

**适配器/主题用 `el-select`**，宽度固定（140px / 120px），
不再手写 `<select>` + 自定义箭头。

### 3.4 源码面板

从「内容区下方直接铺开」改为**右侧抽屉**：

- 默认关闭
- 打开时从右侧滑出，宽 620px，占满高度
- 用 `<pre><code>` + 等宽字体
- 带「复制」按钮
- `Esc` 或点遮罩关闭

**为什么用抽屉而不是下方展开**：
demo 内容通常比源码重要，源码是「需要时查一下」。
下方展开会把 demo 挤到看不见，抽屉则不改变 demo 的布局。

### 3.5 Demo 分组

按组件类型分 6 组：

| 分组 | 包含 |
|---|---|
| 表格 | pro-table/basic、pro-table/with-query、pro-table/selection、crud-page/basic |
| 表单 | query-form/basic、form-generator/basic、form-modal/basic |
| 数据展示 | descriptions/basic、result/basic、page-container/basic |
| 反馈 | feedback/basic |
| 数据看板 | dashboard/basic |
| 可视化大屏 | screen/basic |

分组信息需要 `@fbkworks/demos` 的 registry 提供 `group` 字段。

## 四、URL 直达

当前 demo 与主题写进 URL hash：

```
#/pro-table/basic?adapter=element-plus&theme=light
```

好处：
- 分享链接能还原完整状态
- 浏览器前进/后退可用
- 自动化测试可以直接跳转，不必模拟点击

## 实施结果

### 完成项

| 项 | 状态 |

| 侧边栏 + 6 分组 + 搜索 | ✅ 13 个 demo，搜索可过滤 |

| 源码改右侧抽屉 | ✅ 620px，带复制，Esc 关闭 |
| URL 同步 | ✅ `#/demo-id?adapter=x&theme=y` |
| 删除手写控件样式 | ✅ `playground.css` 中 `appearance: none` 已无 |

### 实施中修正的三处

1. **遮罩太淡**：`rgba(0,0,0,0.28)` 实测几乎看不出效果，改 0.45。
2. **`el-switch` 的 label 在右侧**，视觉上像被挤出视口。改为自定义 label 放左侧。
3. **侧边栏 id 后缀全是 `basic`**，等于没有信息。改为仅在非 basic 时显示。

### 测试调整

`desktop-parity.spec.ts` 里原本有一条断言「Playground 控件显式声明了字体与字号」，
检查 `.playground__field select` 有没有 `font-family: var(--fbk-font-family)`。

**这条断言的意图已经反转**：手写 CSS 对齐令牌，正是这次要消除的做法。
改为断言「顶部使用 el-select / el-switch，且 CSS 里不再有 appearance: none」。
