# 设计稿：极简组件 + 实时监控大屏

> 使用 `frontend-design` 与 `ui-taste` 两个 skill 重新设计。
> ui-taste 对应 playbook：组件 → `distill`，大屏 → `operate`。

---

## 一、诊断：当前设计的问题

### 1.1 组件层

按 `frontend-design` 列的 AI 生成设计特征逐条对照：

| 特征 | 本项目现状 |
|---|---|
| SaaS 卡片套件（同款圆角 + 同层阴影） | **命中**：StatCard / ChartCard 都是 `radius-lg` + `shadow-sm` |
| 卡片套卡片 | **命中**：ChartCard 里嵌 StatCard、ProTable 嵌在卡片里 |
| 到处同一个圆角 | **命中**：`radius-lg` (10px) 用于卡片，`radius-md` (6px) 用于控件，层级差只有 4px |
| 默认蓝主色 | **命中**：`#2f6bff`，任何后台都会选的颜色 |

### 1.2 大屏层

当前是「深色底 + 青色发光 + 网格 + 四角装饰」。

这命中 `frontend-design` 点名的第 2 条：**near-black + 单一亮色 accent**。
也是所有「科技感大屏」的默认做法。

**问题不在于它丑，在于它不是监控语言。** 发光和网格是氛围装饰，
它们不传递任何状态信息。真正的监控界面（示波器、航电仪表、NOC 大屏）
用的是**刻度、状态灯、限值线、时间轴**——每一样都编码信息。

## 二、任务 A：业务组件（极简）

### 2.1 核心决策：去掉容器，用间距分组

`distill` 的建议：*Prefer spacing and alignment over nested cards*。

当前 StatCard：

```
┌─────────────────────────┐  ← 边框 + 圆角 + 阴影
│ 总销售额                 │
│ 1,284,500               │
│ ↑ 12.5% 较上月           │
└─────────────────────────┘
```

改为**无容器**：

```
总销售额
1,284,500
↑ 12.5% 较上月
─────────────            ← 仅一条细分隔线，且在组与组之间
```

去掉：边框、圆角、阴影、背景色。
保留：内边距（保证点击区）、焦点环（可访问性）。

### 2.2 色彩：从「默认蓝」改成低饱和墨蓝

| 令牌 | 现在 | 改为 | 理由 |
|---|---|---|---|
| `--fbk-color-primary` | `#2f6bff` | `#1f3a8a`（墨蓝） | 降低饱和度，减少视觉噪音；文字用它对比度更高 |
| 强调色 | 无 | `#c2410c`（赤陶） | **只用于「需要注意」**，不作为装饰 |

赤陶只出现在三处：负向变化率、错误状态、危险操作。
其余一律灰阶 —— 这样一出现彩色就一定有含义。

### 2.3 字号：建立明确的三级阶梯

当前 `sm/md/lg/xl` = 12/14/16/20，太密，看不出层级。

改为：

| 用途 | 字号 | 字重 | 备注 |
|---|---|---|---|
| 数值（指标卡） | 32px | 600 | 等宽数字，`tabular-nums` |
| 区块标题 | 15px | 600 | |
| 正文 / 表格 | 13px | 400 | 比现在的 14px 更紧凑，提升信息密度 |
| 辅助说明 | 12px | 400 | 次级色 |

### 2.4 圆角：只保留两档，且差距拉大

| 用途 | 值 |
|---|---|
| 控件（按钮/输入框） | 4px |
| 浮层（弹窗/下拉） | 8px |
| 卡片 | **0**（不再有卡片） |

### 2.5 布局：用留白而不是边框分隔

```
┌─────────────────────────────────────────┐
│ 订单列表                                 │  ← 标题
│ 共 128 条，支持多条件筛选                 │  ← 副标题
│                                          │
│ 关键词 [____] 状态 [____] 渠道 [____]    │  ← 查询区，无卡片
│                                          │
│ 新建订单                    [批量删除]    │  ← 工具栏
│ ─────────────────────────────────────── │  ← 唯一的分隔线
│ 订单号  客户  金额  状态  操作            │  ← 表格
│ ...                                      │
└─────────────────────────────────────────┘
```

**只有一条分隔线**：查询区与表格之间。其余靠 24px / 16px 间距分层。

## 三、任务 B：大屏（实时监控仪表盘）

### 3.1 设计方向：仪表盘语言，不是氛围装饰

**去掉**：发光、网格背景、四角装饰、渐变光晕。

**换成**监控界面的四件套：

| 元素 | 作用 | 实现 |
|---|---|---|
| **状态灯** | 3 秒内判断有没有异常 | 每个面板标题左侧一个 6px 圆点：绿=正常 / 琥珀=警告 / 红=异常 |
| **限值线** | 知道「多少算异常」 | 图表上画阈值虚线 + 超限区域淡红填充 |
| **时间轴刻度** | 知道数据新鲜度 | 每 5 秒刷新，右上角显示「最后更新 12:58:31」 |
| **等宽数字** | 数值跳变时不抖动 | `font-variant-numeric: tabular-nums` |

### 3.2 色彩：低饱和深灰蓝 + 语义色

不做纯黑（`#000`）也不做近黑（`#0B0B0B`）—— 两者都是默认套路。

| 令牌 | 值 | 用途 |
|---|---|---|
| 底 | `#14181d` | 带一点蓝的深灰，比纯黑柔和 |
| 面板 | `#1b2027` | 比底亮一档，**不用边框**，靠明度差分层 |
| 主文字 | `#e8ecf0` | |
| 次文字 | `#8b95a1` | |
| 正常 | `#4a9d7f` | 低饱和绿，不刺眼 |
| 警告 | `#c9973f` | 琥珀 |
| 异常 | `#c05a4a` | 砖红 |

**关键：三个状态色都压低饱和度。** 监控大屏是长时间盯的，
高饱和色会视觉疲劳，且会稀释「异常」的警示力。

### 3.3 布局：三区，按信息紧急度排序

```
┌──────────────────────────────────────────────────────────┐
│ 运营监控    ● 全部正常          最后更新 12:58:31   [全屏] │  ← 状态条
├──────────┬───────────────────────────┬───────────────────┤
│ 关键指标  │  主趋势（带阈值线）         │  告警流           │
│ 4 个大数字│                           │  按时间倒序        │
│ 每个带状态│                           │  每条带级别色点    │
├──────────┴───────────────────────────┴───────────────────┤
│ 区域分布        │  渠道占比        │  系统负载            │
└──────────────────────────────────────────────────────────┘
```

**信息优先级**：
1. 状态条（有没有问题）— 最顶，一眼可见
2. 主趋势 + 告警流（问题在哪）— 中间，占最大面积
3. 分布类图表（辅助判断）— 底部，占比小

### 3.4 不做的事

| 不做 | 理由 |
|---|---|
| 发光效果 | 装饰，不编码信息 |
| 网格背景 | 同上 |
| 四角装饰 | 同上 |
| 大标题 + 装饰线 | 值班人员不需要看标题 |
| 环形图旋转动画 | 干扰读数 |

## 五、验收

| 项 | 标准 |
|---|---|
| 组件 | 无卡片边框/阴影；只有一条分隔线；彩色只在有含义处出现 |
| 大屏 | 有状态灯、限值线、最后更新时间；无发光/网格/四角装饰 |
| 对比度 | 沿用已验证的 WCAG 标准（图形 ≥3:1、文字 ≥4.5:1） |
| 主题 | 三套主题下都正确 |
| 门禁 | `pnpm verify` 全绿 |
| 实测 | 浏览器截图确认，不只跑单测 |
